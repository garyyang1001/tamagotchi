# 10 — 開源工具評估

> 這份文件回答一個該在專案開始時就問的問題：
> **`tools/` 底下這七支程式，有多少是在重造輪子？**
>
> 答案：**四支重疊，兩支不重疊，一支根本不該自己寫。**
> 但實測後發現，能取代它們的免費工具都不合用。

---

## 一、重疊分析

| 自製工具 | 開源對應 | 判定 |
|---|---|---|
| `pixedit.py` | Aseprite / LibreSprite | **重造輪子**。用 JSON 描述像素補丁是很糟的像素編輯器 |
| `bake.py` | Aseprite 圖層 + 影格 + CLI 匯出 | **重造輪子** |
| `preview.py` | Aseprite 內建預覽與 GIF 匯出 | **重造輪子** |
| `assemble.py` | Aseprite cel 定位 + **內建 RotSprite** | **部分重造**，且它的旋轉演算法更好 |
| `pack.py`（未寫） | `lv_img_conv`（LVGL 官方） | **不該自己寫** |
| `pixelate.py` | 沒有現成的 | 自製有理 |
| `validate.py` | 沒有現成的 | 自製有理 |

### RotSprite

專案花了大量篇幅論證「旋轉會破壞像素網格」，並為此設計了兩階段烘焙。
但 **RotSprite 這個演算法早就解掉了這個問題**——先放大 8 倍、旋轉、
再猜回像素樣式，而且不引入新顏色。Aseprite 內建它。

兩階段烘焙仍然有價值（它解決的是「每格重新降採樣」而不只是旋轉），
但當初若知道 RotSprite 存在，設計會更快收斂。

### `pixelate.py` 為什麼沒有現成的

標準工具（ImageMagick `-remap`、pngquant）都是**數值最近距離**——
那正是把狗肚子吸成灰白的那個做法。

「同一個來源色在吻部要變灰、在腳要變褐」這種**區域限定的語意指派**找不到現成實作。
它之所以需要，是因為輸入是 **AI 產出的 28,000 色雜訊**，
這不是一般像素美術管線會遇到的狀況。

## 二、實測結果

### LibreSprite v1.1（免費，GPL）

從 Aseprite v1.1.7 於 2016 年分叉。macOS arm64 建置可用。

| CLI 選項 | 有無 | 用途 |
|---|:---:|---|
| `--sheet` | ✅ | 匯出 spritesheet |
| `--save-as` | ✅ | |
| `--frame-range` | ✅ | |
| **`--batch`** | ❌ | **無頭模式** |
| **`--data`** | ❌ | **匯出 JSON atlas** |
| **`--script`** | ❌ | **Lua 自動化** |
| `--split-layers` | ❌ | |
| `--list-tags` | ❌ | |

實測 `--help` **零輸出、掛住直到被砍**（exit 137）。連結 Cocoa/AppKit，永遠嘗試開視窗。

**結論：不能取代自動化管線。** `--batch`、`--data`、Lua 腳本都是 2016 年分叉**之後**
才加進 Aseprite 的，這個分支永遠不會有。

> 已安裝在 `/Applications/libresprite.app`。**當 GUI 像素編輯器用是完全合格的**，
> 見第三節。

### Pixelorama 1.2（免費，Godot）

`--help` 零輸出，只開 GUI。**無頭自動化不可行。**
（另註：homebrew 已標記為 deprecated，2026-09-01 起停止提供，因為過不了 macOS Gatekeeper。）

### Aseprite（$20，原始碼公開但非 OSI 授權）

具備全部需要的：`-b/--batch`、`--sheet`、`--data`、`--script`（Lua）、
`--split-layers`、`--list-tags`、RotSprite。

**未實測**——需要購買或自行編譯（編譯需要 Skia，環境還缺 `cmake` 與 `ninja`）。
任何關於它的敘述都應視為未經本專案驗證。

## 三、結論與現行決策

**保留現有管線，加上 LibreSprite 當手動修圖工具。**

理由：

1. **能取代管線的只有 Aseprite，而它未經驗證且要付費。**
   現有管線七支工具、59 項自我測試全過、可重現性逐位元相同。
   在沒有實測過的替代品面前拆掉它是不理性的。

2. **目前三個未解缺陷都是手動修圖問題，不是管線問題。**

   | 缺陷 | 為什麼管線解不了 | LibreSprite 怎麼解 |
   |---|---|---|
   | `chase_ball` 四條腿不動 | 腿併在 `core` 圖層 | 把腿各自拉成獨立圖層 |
   | 趴姿前腿與胸口有 6px 洞 | 高解析原圖就是分離的 | 筆刷補三筆 |
   | `sleep_breathe` 同上 | 同上 | 同上 |

   這些用免費的 LibreSprite 今天就能修，不需要動管線。

3. **`pack.py` 不要自己寫。** 到了要做裝置資產包時，先評估
   `lv_img_conv`（LVGL 官方，Node.js，支援 I1/I2/I4/I8 索引色與 RGB565）。

## 四、給未來的教訓

> **開工前先查有沒有現成的。**

這個評估該在專案第一天做，而不是在寫完七支工具、跑完數十輪迭代之後。
代價是重造了四支工具，以及繞遠路重新發現了 RotSprite 早已解決的問題。

減損因素：即使當初就查了，結論仍會是「免費的都不合用」——
因為擋路的是 LibreSprite 缺 `--batch`，那不是查資料就會知道的，
要實際下載跑過才會發現。所以真正的教訓不是「查文件」，是**「早點實測」**。
