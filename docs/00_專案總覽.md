一台給 3–5 歲女兒的桌上型電子寵物裝置。螢幕上住著一位冰雪公主，
和三隻依照家裡真實的狗設計的角色。小孩可以餵食、撫摸、陪玩、哄睡。

不是傳統電子雞。傳統電子雞的核心機制是「疏於照顧就會死」，
本專案**刻意移除這個機制**，改成「照顧會得到回應，不照顧只是安靜地等待」。

## 系統分層

```
┌──────────────────────────────────────────────────┐
│  art/reference/    真實照片（人提供）              │
└────────────────────┬─────────────────────────────┘
                     ↓ 人工整理特徵
┌──────────────────────────────────────────────────┐
│  specs/characters/*.json   角色身份規格             │
│  specs/style_lock.md       風格鎖定                │
└────────────────────┬─────────────────────────────┘
                     ↓ tools/mkprompt.py（骨架 + 角色填充 + 動作段落）
┌──────────────────────────────────────────────────┐
│  AI 影像生成：master 10 張 + 動畫影格圖 61 張        │
└────────────────────┬─────────────────────────────┘
                     ↓ 人工 QA（03 的驗收清單）
┌──────────────────────────────────────────────────┐
│  art/approved/     通過的 master                   │
│  art/generated/    一張含全部影格的圖（2×2 四格）    │
└────────────────────┬─────────────────────────────┘
                     ↓ tools/cutstrip.py（切開、對齊、面積正規化）
                     ↓ tools/pixelate.py（降採樣 + 語意重映射 + 保護色）
│  build/strip/<char>/<anim>_px/                    │
                     ↓ tools/bake.py（整數平移 + 翻轉 + 疊圖）
│  build/sheets/  spritesheet + atlas                │
                     ↓ tools/pack.py
│  data/assets.bin   102 個資產、365 格、213,156 B    │
```

關鍵性質：**影格圖以下（cutstrip → pixelate → bake）完全自動化且逐位元可重現**。
動畫調整不需要重新生圖，也不需要美術重畫。

## 為什麼不逐張生成動畫

影像生成模型的每一次推理都是獨立取樣。同一個提示詞、同一張參考圖，
走路循環的第 3 格和第 2 格，毛流走向、耳朵角度、描邊粗細、色階分佈都會不同。
6 fps 播放時這些差異會表現為整體輪廓的高頻抖動，俗稱 boiling。

規格表能防止**設計**漂移（比例、毛色、造型），防不了**像素**漂移。

當初的結論是「唯一的解法是讓每一格重複使用同一批像素，也就是部件切分」——
**那個結論是錯的**，部件路線已於 2026-08-01 刪除（見本文開頭的警告）。
真正的解法是**一次推理畫出全部影格**：同一張圖裡的多個元素不會互相漂移，
而分成多次生成一定會。腳掌也因此是模型畫的、貼在地上，不是繞肩關節轉出來的。

附帶效益：

- Flash 用量 `data/assets.bin` 實測 **208.2 KB**，佔 6 MB `assets` 分區的 3.39%
- 左右方向、`transform` 型的位移與時長都由 baker 從 JSON 產生，不必重畫
- 動畫調整（時長、位移、影格順序）改 JSON 重新烘焙即可，不必重新生圖；
  但**新增一個動畫仍然要生一張新的影格圖**——這是換掉部件路線付出的代價
