# 07 — 角色定義契約

> 這份文件定義「一個角色算不算做完」。
> 判準不是主觀的「看起來好了」，而是 `tools/validate.py` 跑得過。

---

## 一、可重現的硬性定義

**角色的所有資產都必須能從歸檔的來源檔重新產生，且結果逐位元相同。**

```bash
sh art/approved/<id>/REBUILD.sh
git diff --exit-code art/approved/<id>/
```

第二行沒有輸出才算通過。

這條規則的意義：**沒有任何一步是手工在影像編輯器裡做的。**
所有修改都存在版控裡的 JSON（`remap` 與 `patch`），任何人任何時候都能重建。
半年後想調整某個顏色，改 JSON 重跑就好，不需要找到當初的 PSD、
不需要記得當初在 Photoshop 裡做了什麼。

一個角色若無法通過這條，就不算定義完成，不論看起來多好。

## 二、三個層級

角色不是全有全無。分三層，**每一層都是可跑的**。

### Tier 0 — 可跑（只需要 master sprite）

在 64px 的尺度下，很多動作用「整隻 sprite 的位移、縮放、傾斜」就足夠，
不需要拆部件。這是電子雞類遊戲的正確精細度——原版電子雞每個動作只有 2 格。

**Tier 0 完成即可在裝置上跑起來。**

必要檔案：

| 檔案 | 內容 |
|---|---|
| `specs/characters/<id>.json` | 身份特徵、比例、狀態 |
| `specs/palettes/<id>.json` | 16 色，index 0 透明 |
| `art/approved/<id>/master_stand_r_source.png` | AI 原始輸出，未經處理 |
| `art/approved/<id>/master_stand_r.remap.json` | 語意色彩對照 |
| `art/approved/<id>/master_stand_r.patch.json` | 手工像素修補 |
| `art/approved/<id>/master_stand_r_64px.png` | 成品 sprite |
| `art/approved/<id>/REBUILD.sh` | 重現指令 |
| `specs/animations/<id>.anim.json` | 全部 21 個動畫，Tier 0 的用 `transform` |

### Tier 1 — 有表情（需要部件）

耳朵、尾巴、眼瞼這些小動作是角色個性的來源，
但它們不影響「能不能跑」。

追加檔案：

| 檔案 | 內容 |
|---|---|
| `art/rigs/<id>/rig.json` | 部件階層、pivot、z-order |
| `art/rigs/<id>/*.png` | 16 個部件圖 |
| `art/approved/<id>/B3_parts_source.png` | 部件分解圖原始輸出 |

### Tier 2 — 完整（需要姿態）

坐姿與趴姿由 rig 旋轉部件推導，不足處用 `pixedit.py` 補。
**不另外生成姿態圖**——實測換姿勢會造成身分漂移，見 `docs/05`。

## 三、影格預算

電子雞不需要精細動畫。影格數的上限如下，**超過會被 validator 擋下**。

不是省不起 flash，是**過多的影格在 64px 上看不出差別**，
而且會讓動作變得軟綿綿——像素動畫的力量來自明確的姿勢對比，不是流暢的補間。

### Tier 0 — 整體變換，不需部件

| 動畫 | 影格 | fps | 做法 |
|---|---:|---:|---|
| `idle_breathe` | 4 | 4 | 整體上下 1 px |
| `sad_wait` | 4 | 3 | 整體下沉 1 px，節奏更慢 |
| `happy` | 6 | 10 | 整體彈跳 + 微幅縮放 |
| `eat` | 4 | 6 | 整體前傾 + 上下啄 |
| `eat_happy` | 6 | 8 | 彈跳 + 左右微搖 |
| `sleep_breathe` | 4 | 2 | 極緩起伏 |
| `walk` | 4 | 8 | 上下 1 px + 水平位移 |
| `chase_ball` | 4 | 12 | 同 walk 但更快、幅度更大 |
| `pet_react` | 4 | 6 | 整體微微傾向撫摸方向 |
| `yawn` | 4 | 5 | 整體拉伸再放鬆 |
| `toilet` | 4 | 5 | 整體下蹲 |

小計 **48 格**。

### Tier 1 — 需要部件

| 動畫 | 影格 | fps | 動的部件 |
|---|---:|---:|---|
| `idle_blink` | 3 | 10 | eyelid |
| `idle_ear_twitch` | 4 | 8 | ear_near / ear_far |

| `play_bow` | 4 | 8 | torso + 前腿 |
| `turn` | 3 | 8 | 整體翻轉過渡 |

小計 **22 格**。

### Tier 2 — 需要姿態

| 動畫 | 影格 | fps |
|---|---:|---:|
| `sit_down` | 4 | 8 |
| `stand_up` | 4 | 8 |
| `lie_down` | 4 | 8 |
| `wake_up` | 4 | 6 |

小計 **16 格**。

### 總計

```
每角色  86 格（原規劃約 190 格，砍掉 55%）
四角色  344 格
單格    64×54 4bpp 索引，RLE 後約 700 B
合計    約 240 KB
```

`assets` 分區 6 MB → 餘裕 **25 倍**。

## 四、動畫定義的兩種寫法

`specs/animations/<id>.anim.json` 的每個動畫用 `type` 區分：

### `transform` — Tier 0

整隻 sprite 的變換，不引用任何部件。

```json
{
  "id": "idle_breathe",
  "type": "transform",
  "tier": 0,
  "loop": true, "fps": 4, "frames": 4,
  "track": [
    { "f": 0, "y": 0 },
    { "f": 1, "y": -1 },
    { "f": 2, "y": 0 },
    { "f": 3, "y": 0 }
  ]
}
```

可用欄位：`x` `y`（像素位移）、`scale`（百分比）、`rot`（度）、`flip`（水平翻轉）。

> **位移必須是整數像素。** 非整數位移會破壞像素網格，看起來會糊。
> validator 會擋下小數。

### `rig` — Tier 1 / 2

各部件的關鍵影格，格式見 `specs/animations/brown_mixed.anim.json`。

## 五、驗證

```bash
python tools/validate.py --character brown_mixed
```

檢查項目：

**規格層**
- [ ] `characters/<id>.json` 存在，無 `TBD_FROM_PHOTO` 殘留，`status` 為 `APPROVED`
- [ ] `palettes/<id>.json` 恰好 16 色，index 0 為透明，role 名稱無重複

**資產層**
- [ ] master sprite 存在，色數 ≤ 16
- [ ] master sprite 用到的每個顏色都在調色盤內（不能有調色盤外的雜色）
- [ ] `REBUILD.sh` 存在且可執行
- [ ] **重跑 `REBUILD.sh` 產出與歸檔檔案逐位元相同** ← 可重現的硬性判準

**動畫層**
- [ ] 涵蓋 `game.h` 的全部 21 個 `anim_id_t`，不多不少
- [ ] 每個動畫的影格數不超過第三節的預算
- [ ] `transform` 型的位移都是整數
- [ ] `rig` 型引用的部件都存在於 `rig.json`

**分層**
- [ ] 回報目前達到 Tier 0 / 1 / 2 的哪一層，以及升級到下一層還缺什麼

**辨識度**（詳見 `docs/09_角色辨識設計.md` 第九節）

前兩項可以自動化，第三項必須是真人：

- [ ] **填黑剪影測試** — 三隻填成純黑，1× 縮放下能分出誰是誰
- [ ] **灰階測試** — 去色後三隻的整體明度明顯不同
      （`chihuahua` 最亮 / `brown_mixed` 中 / `brindle_guard` 最暗）
- [ ] **3 歲測試** — 實際螢幕、1× 縮放、手臂距離、只看 1 秒。
      問「這是哪一隻？」不要問「這是不是 XX？」
- [ ] 眉點等簽名標記至少 2×2，不是細橫條也不是單像素
- [ ] 標記位置在所有影格與姿勢中都沒有移動過一格

> 辨識度測試要三隻狗都做完才有意義（是相對比較，不是絕對標準）。
> 單一角色階段先記錄數值，等三隻齊了再一起驗。
