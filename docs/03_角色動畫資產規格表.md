> **這份文件是所有角色圖檔的唯一依據。**
> 在 `art/reference/` 收到真實照片、且本文件第三節的 `TBD_FROM_PHOTO` 欄位全部填完之前，
> **不要開始生成任何角色圖**。

>
> 美術方向從「平塗插畫」改為**真像素藝術**。這個改變同時解掉了兩個包袱：

> 1. 原本要三令五申「不准用漸層」的規則，變成像素風的自然結果——

> 2. 真像素角色本身就小，**四角色同框只要 254 px（< 320）**，
>    原本規劃的兩套縮放比例（`solo` / `group`）整個不需要了
>
> 受影響的章節（一、二、五）已更新。**生成端的實測規則與工具用法見 `docs/05_資產管線.md`。**

>

## 一、全域母版規格

| 項目 | 規格 |
|---|---|
| 生成尺寸 | 向 gpt-image-2 要 **1024 × 1024**（實際輸出會不同，見下） |
| 生成背景 | **純洋紅 `#FF00FF`**。gpt-image-2 不支援透明背景 |
| 最終 sprite | **64 × 64 格**（狗實測填滿約 64 × 53） |
| 格式 | PNG，RGBA，1-bit alpha |
| 視角 | 3/4 側面，視平線在角色胸高 |
| 描邊 | 深色統一描邊，最終 sprite 上**恰好 1 px** |
| 色彩 | 每角色 **≤ 16 色**（含透明 index 0） |
| 陰影 | 接地陰影為**獨立部件**，不畫在角色身上 |

> ⚠️ **不要依賴指定的生成尺寸。** 實測要 1024×1024 得到 1341×1173，
> 要 1536×1024 得到 1774×887。`tools/pixelate.py` 會裁到內容範圍再縮放，
> 所以輸出尺寸不一致沒有影響。

### 風格硬性規則

裝置端貼圖是 16 色索引 + 1-bit alpha。因此必須：

✅ 平塗，每個材質最多 3 階（暗 / 中 / 亮）
✅ 清晰封閉的深色描邊，最終 sprite 上 1 px
✅ 色塊邊界銳利，大片單色區域

❌ 漸層 / 噴槍柔邊 / 半透明 / 發光 / 模糊
❌ 寫實毛髮渲染、逐根毛、照片材質

**這不是美感偏好，是硬體限制。** 有漸層的圖量化到 16 色會出現嚴重色帶，
RLE 壓縮率也會從 2.5× 掉到接近 1×。

完整提示詞風格區塊見 `specs/style_lock.md`，**一字不改地貼進每次生成**。

> **最重要的一條**：提示詞只寫 "pixel art" 不夠。實測模型會理解成
> 「畫高細節圖再套像素化濾鏡」，等效解析度會到 150×160，細節全糊在一起。
> 必須明確寫出目標像素尺寸並強調 "genuinely low-resolution"。

## 二、四角色比例鎖定表

以 512 母版座標系，站立姿態測量。**這張表一旦定案就不再改動。**

| 角色 | 全高(px) | 佔公主比 | 體長(px) | 肩高(px) | 頭身比 | 眼睛佔頭寬 |
|---|---:|---:|---:|---:|---|---:|
| `ice_princess` | **420** | 100% | — | — | 4.5 頭身 | 20% |
| `chihuahua` | **145** | 34.5% | 165 | 105 | 3 頭身 | 22% |
| `brown_mixed` | **250** | 59.5% | 300 | 195 | 3.5 頭身 | 15% |
| `brindle_guard` | **265** | 63.1% | 310 | 210 | 4 頭身 | 16% |

### 關於吉娃娃的刻意放大

真實比例下，吉娃娃相對於一個 4 歲女孩約為 **28%**。本表用 **34.5%**，
刻意放大約 6 個百分點。理由：在 `group` 縮放下（70%），
28% 會讓吉娃娃只有 **32 px 高**，臉部特徵完全消失，小孩認不出那是誰家的狗。
34.5% 換算為 40 px，剛好保住耳朵形狀與額頭白線的辨識度。

這是**唯一一處**允許偏離真實比例的地方，其餘一律照實。

### 輸出尺寸（單一比例，不需要兩套縮放）

改成真像素藝術之後，角色本身就小，四角色同框放得進 320 px，
所以**不需要 `solo` / `group` 兩套縮放**。這是改用像素風的直接收益。

| 角色 | sprite 高 | sprite 寬 | 說明 |
|---|---:|---:|---|
| `ice_princess` | 105 | 60 | |
| `chihuahua` | 36 | 41 | |
| `brown_mixed` | 62 | 75 | 實測 64px 格內為 64×53 |
| `brindle_guard` | 66 | 78 | |
| | | **254** | **四角色同框總寬 < 320** ✓ |

sprite 格統一 **64 × 64**（公主用 64 × 112）。空白區域由 RLE 壓到接近零成本。

> **真像素藝術不可以在裝置端縮放。** 任意比例縮放會破壞像素網格，
> 看起來會很糟。所有尺寸在 build time 就決定好。

## 四、調色盤規格

每角色一組 **16 色**（index 0 固定為透明）。定義在 `specs/palettes/<char>.json`。

以吉娃娃為例的配置邏輯：

| idx | 用途 | idx | 用途 |
|---:|---|---:|---|
| 0 | 透明 | 8 | 淺褐 中 |
| 1 | 描邊（深棕黑） | 9 | 鼻／肉墊 深 |
| 2 | 棕毛 暗 | 10 | 眼 深色 |
| 3 | 棕毛 中 | 11 | 眼 高光（白） |
| 4 | 棕毛 亮 | 12 | 舌／口內 粉 |
| 5 | 白毛 暗（灰藍調） | 13 | 耳內 粉 |
| 6 | 白毛 中 | 14 | 接地陰影 |
| 7 | 白毛 亮 | 15 | 項圈識別色 |

**規則**：
- 每個材質最多 3 階（暗/中/亮），這決定了 16 色夠不夠用
- 白色不要用純 `#FFFFFF`，用微帶藍灰的白，看起來才有體積
- 描邊色不要用純黑，用材質色的極深版本
- index 15 保留給角色識別色（項圈），四隻狗要明顯不同

`tools/validate.py` 會檢查母版圖的實際色數，超過 16 色直接報錯。

## 五、部件切分規格（rig）

> ### ⚠️ 真像素藝術與部件旋轉的衝突
>
> 旋轉像素藝術會破壞像素網格，結果會出現不對齊的鋸齒。
> 解法是**在高解析度合成與旋轉，最後才像素化**：
>
> ```
> 部件圖（高解析，AI 原始輸出的解析度）
>   → bake.py 合成 + 旋轉（仍在高解析）
>   → pixelate.py 降到 64px（每一格用同一組格線與同一個調色盤）
>   → spritesheet
> ```
>
> 這樣旋轉發生在像素化之前，最終輸出仍是乾淨對齊的網格。
> 但必須遵守兩條鐵律，否則動畫會抖動或閃爍——見 `docs/05_資產管線.md` 第三節。
>
> **所以部件圖保存在 AI 原始解析度，不要先像素化再切分。**

### 5.1 犬類部件階層

```
root                             (原點 = 地面接觸點)
├── shadow                       接地橢圓陰影
└── body            [pose]       pivot: 髖部中心
    ├── tail                     pivot: 尾根
    ├── leg_hind_far  [pose]     pivot: 髖
    ├── leg_hind_near [pose]     pivot: 髖
    ├── leg_fore_far  [pose]     pivot: 肩
    ├── leg_fore_near [pose]     pivot: 肩
    └── head                     pivot: 頸根
        ├── ear_far              pivot: 耳根
        ├── ear_near             pivot: 耳根
        ├── eye_far              固定
        ├── eyelid_far           pivot: 上眼瞼，靠 y 位移做眨眼
        ├── eye_near             固定
        ├── eyelid_near          pivot: 上眼瞼
        ├── muzzle               固定
        │   ├── jaw              pivot: 下顎關節，靠旋轉開合嘴
        │   └── tongue           顯示/隱藏
        └── (marking_overlay)    僅 mirror 修正用，可選
```

`[pose]` 標記的部件有三套姿態版本：**`stand` / `sit` / `lie`**。
坐姿與趴姿的軀幹與腿部形狀無法由旋轉得到，必須另外畫。

**眨眼用眼瞼位移而非三張眼睛圖**——1 張眼瞼取代 3 張眼睛狀態圖，
而且可以做出任意中間值的半瞇眼。開合嘴同理，用下顎旋轉取代 4 張嘴型。

### 5.2 公主部件階層

```
root
├── shadow
├── hair_back
├── arm_far_upper / arm_far_fore      pivot: 肩 / 肘
├── leg_far           [pose]
├── torso             [pose]          pivot: 髖，服裝為獨立覆蓋層
├── leg_near          [pose]
├── arm_near_upper / arm_near_fore    pivot: 肩 / 肘
│   └── hand_anchor                   掛點（無圖），手持物件用
├── head                              pivot: 頸根
│   ├── hair_front
│   ├── eye_L / eyelid_L
│   ├── eye_R / eyelid_R
│   ├── brow_L / brow_R               pivot: 眉心側
│   ├── mouth                         3 態：閉 / 微笑 / 張
│   ├── blush                         可選層
│   └── crown                         可選層
└── outfit_overlay                    服裝獨立層，套在 torso 上
```

姿態版本：**`stand` / `sit` / `kneel`**（跪下摸狗用）。

## 六、AI 生成批次（實際只需 ~36 張生成）

不逐張生成 205 個部件。改成生成 **部件分解圖（breakdown sheet）**：
一張圖上把所有部件攤開排列在透明背景上，再用 `tools/cutparts.py` 自動切開。

| 批次 | 內容 | 張數 |
|---:|---|---:|
| **B0** | 四角色標準模型表（正面+左右側+背面，含比例尺） | 4 |
| **B1** | 四角色比例對照圖（同一畫面站在一起） | 1 |
| **B2** | 每角色表情表（8 種情緒的頭部特寫） | 4 |
| **B3** | 部件分解圖 — stand 姿 | 4 |
| **B4** | 部件分解圖 — sit 姿 | 4 |
| **B5** | 部件分解圖 — lie / kneel 姿 | 4 |
| **B6** | 鏡射方向補畫（虎斑全套 ×3、吉娃娃頭部、公主頭部） | 5 |
| **B7** | 公主服裝表（5 套） | 1 |
| **B8** | 物件表（食物 / 玩具 / 家具 / 特效 / UI 圖示） | 5 |
| **B9** | 場景背景（臥室 / 用餐 / 遊戲 / 夜晚） | 4 |
| | **合計** | **36** |

計入重生與挑選的損耗（約 2×），實際生成次數約 **70 次**。

**批次之間必須循序完成，不可跳批。**
B0 未通過驗收前不做 B1，B1 未定案前不做 B2 以後的任何一批。
這就是原始規劃裡「先做四角色標準模型表」的正確執行方式。

### 7.4 總量與 Flash 驗算

```
動畫總數    21 × 3 + 21 + 6 = 90
平均影格數  9
烘焙影格    90 × 9 ≈ 810

單格（solo 最大 112×88）:
  4bpp 索引        112 × 88 ÷ 2 = 4,928 B
  RLE 後（實測約 2.5×）  ≈ 1,970 B

810 × 1,970 ≈ 1.60 MB
加上 group 縮放的常用動畫（+15%）  ≈ 1.84 MB
加上物件 / UI / 場景             ≈ 2.4 MB
```

`assets` 分區 **6 MB** → 餘裕 **2.5×**。✅

對照：原規劃的 250 張 128×128 RGB565 未壓縮 = **7.81 MB**，已經超過可用空間。
部件路線在動畫數量多 3 倍的情況下，佔用只有原方案的 **31%**。

> **備援方案**：若日後動畫量再膨脹到塞不下，可改為裝置端執行期合成
> （只存 205 個部件圖，約 0.4 MB）。代價是 CPU 開銷。
> 目前 flash 餘裕充足，優先選擇烘焙好的完整影格，換取執行期零成本。

## 八、檔案命名

### 部件圖（`art/rigs/<char>/`）

```
<character>_<pose>_<part>_<dir>.png
```
```
chihuahua_stand_body_r.png
chihuahua_stand_leg_fore_near_r.png
chihuahua_head_ear_near_r.png
chihuahua_head_eyelid_far_l.png       ← 鏡射不安全，另畫
brindle_guard_sit_body_l.png
ice_princess_kneel_torso_r.png
```

- `<pose>`：`stand` / `sit` / `lie` / `kneel` / `head`（頭部群不分姿態）
- `<dir>`：`r`（面向右，基準方向）/ `l`（面向左，僅 `mirror_safe: false` 的部件需要）

### 烘焙產物（`build/sheets/`）

```
<character>_<anim>_<dir>_<profile>.png      spritesheet
<character>_<anim>_<dir>_<profile>.json     atlas（每格位置、anchor、時長）
```

### 生成原圖（`art/generated/`）

```
<batch>_<character>_<shot>_<序號>.png
B3_chihuahua_breakdown_stand_03.png
```

保留所有生成結果（含被退回的），方便回溯與比對。

## 九、生成提示詞規範

每次生成的提示詞由 **四個區塊**組成，由 `tools/genprompt.py` 自動拼接：

```
[1] STYLE LOCK      ← specs/style_lock.md，逐字不變
[2] CHARACTER       ← specs/characters/<char>.json 的 identity_features
[3] SHOT            ← 本次要的視角 / 姿態 / 版面
[4] CONSTRAINTS     ← 負面約束（無背景、無漸層、無文字浮水印…）
```

**強制規則**：

1. **[1] STYLE LOCK 一字不改。** 這是跨角色風格一致的唯一保證。
   改了它，四個角色就不會像是同一個世界的。
2. **B1 之後的每一次生成都必須附上已通過的參考圖**作為影像輸入
   （`art/approved/` 裡的模型表）。純文字生成無法維持角色一致性。
3. 一次只生成一個角色。**不要在同一張圖裡生兩隻狗**（B1 比例對照圖除外）。
4. 部件分解圖要在提示詞裡明確要求「各部件之間留白分開、不重疊、透明背景」。

## 十、QA 驗收清單

每一張生成圖進 `art/approved/` 前，逐項確認。**任一項不過就退回重生。**

### 通用

- [ ] 背景完全透明，無殘留白邊或棋盤格
- [ ] 無漸層、無柔邊、無發光、無模糊
- [ ] 描邊完整封閉，粗細一致
- [ ] 實際色數 ≤ 16（跑 `python tools/validate.py --image <path>`）
- [ ] 無文字、無浮水印、無簽名
- [ ] 視角為 3/4 側面，與前一批一致
- [ ] 光源方向與前一批一致（預設左上 45°）

### 比例

- [ ] 角色全高符合第二節的比例鎖定表（±3%）
- [ ] 頭身比正確
- [ ] 眼睛佔頭寬比例正確
- [ ] 與同批其他角色並排時，相對大小正確

### 身份特徵（逐角色對照第三節）

- [ ] 三節裡該角色的每一項 `identity_features` 都出現且正確
- [ ] 毛色與參考照片一致（並排比對，不憑印象）
- [ ] **不對稱特徵在正確的一側**
- [ ] 虎斑護衛犬：未露牙、未皺鼻、無威嚇姿態

### 部件分解圖額外檢查

- [ ] 所有必要部件都在，沒有漏
- [ ] 部件之間有留白，沒有重疊或相黏
- [ ] 同一部件在不同姿態圖裡的**顏色完全一致**
- [ ] 關節處有足夠的重疊餘量（旋轉時不會露出縫隙），建議 8 px

## 十一、實際製作順序

```
0. 收齊真實照片 → 填完本文件所有 TBD_FROM_PHOTO 欄位
                → 決定公主髮辮側、四隻狗的項圈識別色
1. 撰寫 specs/style_lock.md 與 specs/characters/*.json
2. B0  四角色標準模型表 ────────── QA 通過才繼續
3. B1  四角色比例對照圖 ────────── 這張是全案的定海神針
4. 建立 specs/palettes/*.json（從 B0/B1 取色）
5. B2  表情表
6. B3–B5  部件分解圖
7. B6  鏡射方向補畫
8. tools/cutparts.py 切分 → art/rigs/<char>/ + rig.json
9. 寫第一個動畫 idle_breathe → tools/preview.py 確認 → 對了再寫其餘
10. B7–B9 物件 / 場景
11. tools/bake.py + tools/pack.py → data/assets.bin
```

**步驟 3 的四角色比例對照圖是整個專案最重要的一張圖。**
它一旦定案，後面兩百多張圖才有共同的基準。在它通過驗收之前，
不要因為想快一點就先做別的批次。
