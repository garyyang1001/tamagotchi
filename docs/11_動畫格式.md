# 11 — 動畫格式

> `specs/animations/<id>.anim.json` 的權威定義，以及 `tools/bake.py` 怎麼消費它。
> 動畫調整一律改這個 JSON 重新烘焙，**永遠不要重新生圖**。
>
> **2026-08-02 更新**：`type: "rig"`（部件旋轉路線）已經連程式碼一併移除。
> 本文件原本有一半在講它。現在只剩兩種型別：`frames` 與 `transform`。

---

## 一、烘焙只做三件事

```
整數像素平移  +  水平翻轉  +  z 排序  +  疊圖
```

沒有第五件。**不重新採樣、不旋轉、不縮放、不做 alpha 混合、不做非整數位移。**

這不是保守，是這一層存在的全部理由。本專案的降採樣比是 21:1
（1344×1176 → 64×56），一條腿只有 7 像素寬、眼瞼只有 3.5 像素高。
在高解析度「把後腿轉 25 度」，在輸出端的全部意義是把腿下段的 3 個像素
往旁邊挪 2 格——而挪哪幾格由降採樣格線與旋轉角度的交互作用決定，不受我們控制。
那就是閃爍，也是 Dead Cells 至今沒解掉的那個問題（見 `docs/05` 第三節）。

旋轉沒有被放棄，是**整條路線被放棄了**：實測單段式部件繞肩關節旋轉會讓腳掌
畫弧離開地面，`walk` 與 `idle_breathe` 產出完全相同的影格。
現在的做法是請影像模型一次畫出一張含全部影格的圖，再切開——
模型畫的腳掌是貼地的，而且同一張圖內不會漂移（單次推理）。

```bash
.venv/bin/python tools/bake.py --character brown_mixed \
    --anim      specs/animations/brown_mixed.anim.json \
    --out-dir   build/sheets
```

## 二、檔案骨架

```json
{
  "character_id": "brown_mixed",
  "format_version": 2,
  "defaults": { "fps": 6, "loop": false, "type": "transform" },
  "animations": [ ... ]
}
```

`defaults` 提供 `type` / `fps` / `loop` 的預設值，個別動畫可覆寫。

每個動畫共通的欄位：

| 欄位 | 必要 | 說明 |
|---|:--:|---|
| `id` | 是 | 必須對應 `firmware/include/game.h` 的 `anim_id_t` |
| `type` | | `frames`（AI 生成的影格）或 `transform`（整張 master 位移／翻轉） |
| `frames` | 是 | 影格數。上限見 `docs/07` 第三節，`validate.py` 會擋 |
| `frame_ms` | | **權威的時間欄位**，每格毫秒數 |
| `fps` | | 只在沒有 `frame_ms` 時用來反推（`round(1000/fps)`） |
| `loop` | | 是否循環 |
| `tier` / `desc` / `status` | | 給人看的中繼資料，bake.py 原樣抄進 atlas |

> **為什麼 `frame_ms` 是權威而不是 `fps`**：真實犬隻休息呼吸 10–30 次/分，
> 4 格的呼吸循環要 2–6 秒，換算成 fps 是 0.67–2.0 的小數。整數 fps 表達不了，
> 而寫成小數 fps 再四捨五入回毫秒，`1.33 fps` 會變成 752ms 而不是作者要的 750ms。

## 三、`type: "transform"` — Tier 0

整隻 sprite 的整數位移與水平翻轉，來源是
`art/approved/<id>/master_stand_r_64px.png`，完全不碰部件。

```json
{
  "id": "idle_breathe",
  "type": "transform",
  "tier": 0,
  "loop": true,
  "frames": 4,
  "frame_ms": 750,
  "track": [
    { "f": 0, "y":  0 },
    { "f": 1, "y": -1 },
    { "f": 2, "y": -1 },
    { "f": 3, "y":  0 }
  ]
}
```

`track` 的可用欄位：

| 欄位 | 型別 | 預設 | 說明 |
|---|---|---:|---|
| `f` | 整數 | — | 影格編號，`0 ≤ f < frames`，不可重複 |
| `x` | 整數 | 0 | 水平位移，正值往畫面右邊 |
| `y` | 整數 | 0 | 垂直位移，**負值向上** |
| `flip` | 0/1 | 0 | 水平翻轉，以畫布中線為軸 |
| `ms` | 正整數 | `frame_ms` | 這一格的顯示時間，可做不等長節奏 |

`rot` 與 `scale` **已從格式中移除**。旋轉破壞像素網格；非等比縮放讀起來是
「狗被壓扁」而不是「狗坐下」——實測把 `sit_down` 寫成 `scale_y: 86%` 就是這樣。
**坐姿是不同的剪影，不是同一個剪影變矮。**

## 四、`type: "frames"` — 主力型別

影格已經是完成品：AI 一次生成一張含全部影格的圖，`cutstrip.py` 切開對齊、
`pixelate.py` 降採樣，bake.py 只負責串成 spritesheet。

```json
{
  "id": "walk",
  "type": "frames",
  "tier": 1,
  "loop": true,
  "frames": 4,
  "frame_ms": 140,
  "frames_dir": "build/strip/brown_mixed/walk_px",
  "source_sheet": "art/generated/B4_brown_mixed_walk.png",
  "screen_offset": [ { "f": 0, "y": 0 }, { "f": 1, "y": -1 } ]
}
```

| 欄位 | 必要 | 說明 |
|---|:--:|---|
| `frames_dir` | 是 | 影格 PNG 的目錄。依檔名排序，數量必須正好等於 `frames` |
| `reverse` | | 倒著讀同一個目錄。`stand_up` 就是倒放的 `sit_down` |
| `source_sheet` | | 生成來源，給人追溯用 |

### 4.1 影格檔的硬性要求

* 檔名要符合 `*_f<N>_64px.png`——那是 `pixelate.py` 的輸出檔名決定的
* **每一格必須是完整畫布**（等於 `render.sprite_cell`）。
  逐格裁切會讓角色偏掉，所以 `pixelate.py` 一定要加 `--no-crop`。
  bake.py 會擋下尺寸不符的影格
* 只能用調色盤裡的顏色，alpha 只能是 0 或 255

### 4.2 `frames` 型不接受 `track`

影格已經是完成品，`track` 的位移不會有作用。寫了會直接報錯——
留著會讓人以為位移生效了。要位移就用 `screen_offset`（繪製時偏移，不烘進影格）。

### 4.3 `reverse` 為什麼值得

Digimon V-Pet 用 12 張 sprite 撐出 8 種行為就是靠這招。
省一次生成，而且保證兩個方向完全對稱——手動畫反向一定會有微差。

四個角色各有兩個反向動畫：`stand_up` ← `sit_down`、`wake_up` ← `lie_down`。

## 五、關鍵影格是**步進**，不是補間

> 兩個關鍵影格之間**不做任何插值**。每一格取「`f` 小於等於它的最後一個關鍵影格」的值。

理由有兩個，都不是風格偏好：

1. **像素動畫的力量來自明確的姿勢對比。** 補間出來的中間姿勢在 64px 上讀不出來，
   只會讓動作變得軟綿綿（`docs/07` 第三節同一個理由砍掉了 55% 的影格）。
2. **補間必然產生非整數位移。** `dx` 從 0 到 3 補三格會得到 1.0 / 2.0 這種看似
   安全的值，但只要幅度不是整除就會出現 1.5，而 1.5 一定要 round——
   round 就是格線漂移，格線漂移就是閃爍。

**每個欄位各自延續自己最後出現的值**（per-field step-hold），
所以 `{"f":2,"show":false}` 不需要重寫 `dx`/`dy`。

一個 4 格的例子：

```json
"track": [ { "f": 1, "x": 5 }, { "f": 2, "y": -2 } ]
```

| 影格 | `x` | `y` | 為什麼 |
|---:|---:|---:|---|
| 0 | 0 | 0 | 還沒有任何關鍵影格，用預設值 |
| 1 | 5 | 0 | `f=1` 指定了 `x` |
| 2 | 5 | -2 | `x` 延續 f1，`y` 被新指定 |
| 3 | 5 | -2 | 兩者都延續 |
| 3 | 5 | true | `dx` 仍然延續 f1 |

## 六、`screen_offset` — 繪製時的偏移

`screen_offset` 的欄位與 `track` 相同，但它**不烘進影格**：
bake.py 把它逐格記進 atlas 的 `screen_dx` / `screen_dy`，由渲染層套在繪製座標上。

為什麼要有這個：影格畫布只比角色高 2-6 列。`happy` 想跳 7 px 的話，
前三格的頭頂與耳尖會被畫布切掉。但角色跳起來本來就是在螢幕空間移動，
不需要更高的影格——把位移交給渲染層，影格保持乾淨，跳多高都不會被切。

四個角色的 `happy` 與 `sad_wait` 全部走這條路，`track` 的 y 一律 0。

## 七、輸出

```
build/sheets/<character>_<anim>.png        水平排列的 spritesheet
build/sheets/<character>_<anim>.json       每格的 x/y/w/h、ms、flip、screen_dx/dy
build/sheets/<character>_<anim>_x8.png     放大預覽（最近鄰，--scale 0 可關）
build/sheets/<character>_atlas.json        全部動畫的索引
```

索引裡每個動畫都附 `sha256_12`，可用來確認「改 JSON 重新烘焙」真的只動到該動的檔案。

## 八、硬性檢查

做不到就報錯中止，不會默默通過。

| 檢查 | 失敗訊息會指出 |
|---|---|
| 每一格只用調色盤裡的顏色 | 哪個顏色、第一次出現的座標 |
| 位移是 JSON **整數字面值** | 哪個動畫、哪一格、哪個欄位 |
| alpha 只有 0 / 255 | 哪個影格檔、幾個半透明像素 |
| 影格 PNG 尺寸 == 畫布尺寸 | 實際尺寸、預期尺寸，以及「請加 --no-crop」 |
| `frames_dir` 的檔案數 == `frames` | 宣告幾格、實際幾個檔 |
| 關鍵影格 `f` 在範圍內且不重複 | 哪個 `f` |
| track 欄位名沒打錯 | 未知欄位名與可用欄位清單 |
| `frames` 型不得有 `track` | 影格已經是完成品，位移不會有作用 |
| `transform` 型不得有 `layers`/`pose`/`pose_track` | 那些欄位屬於已移除的 rig 路線 |
| `type: "rig"` 一律拒絕 | 路線已移除，請改用 `frames` |

> **連 `2.0` 都會被擋。** 數值上是整數的浮點數也要寫成整數字面值。
> 只要這個欄位可以是浮點數，遲早會有人寫 `2.5`，而 `2.5` 會在下游被某個
> `round()` 悄悄吸掉，變成看不出來的格線漂移。要擋就在最上游擋。

單一動畫失敗不會讓整批中止——bake.py 會把所有問題一次列完，
但**離開碼非零，而且不寫 atlas 索引**。下游 `pack.py` 寧可立刻找不到檔案，
也不要拿到一份看起來完整、其實缺格的資產包。要保留部分結果請加 `--keep-going`。

### 越界像素

位移把不透明像素推出畫布時，bake.py 會計數並在輸出與 atlas 裡標示，
`--strict-clip` 可以把它升級成錯誤。這是警告而不是預設錯誤，因為裁掉幾個
像素有時是刻意的（走出畫面）。

## 九、影格尺寸（已解決）

本節原本記錄一個矛盾：四份文件各自寫著 64×56 / 64×54 / 64×64 / 64×53，
而 `happy` 與 `sad_wait` 有 179 px 被畫布切掉。

**兩件事都解決了：**

1. **尺寸的真相來源只有一個**：`specs/characters/<id>.json` 的 `render.sprite_cell`，
   由 `tools/cell.py` 供給 cutstrip / bake / procanim。
   四個角色是 64×56 / 64×56 / 64×56 / **64×96**（公主是人形，站起來是狗的兩倍高）。
   `brown_mixed` 的規格檔曾經寫錯成 `[64, 64]` 很久沒被發現——就是因為那時候
   沒有任何程式讀它。`cell.py` 進來的第一天測試就抓到了。

2. **裁切的問題改用 `screen_offset` 解**（見第六節）：
   彈跳與下沉的位移交給渲染層，`track` 的 y 一律 0。
   四個角色現在都是零切邊，`test_bake.py` 的最後一項在守這件事。

## 十、完整範例

**`frames` 型**（主力，17/21 個動畫走這條）：

```json
{
  "id": "walk",
  "type": "frames",
  "tier": 1,
  "loop": true,
  "frames": 4,
  "frame_ms": 140,
  "fps": 7.14,
  "status": "IMPLEMENTED",
  "desc": "走路。AI 一次生成的四格（2x2），腳掌貼地、腿在關節彎曲。",
  "frames_dir": "build/strip/brown_mixed/walk_px",
  "source_sheet": "art/generated/B4_brown_mixed_walk.png",
  "screen_offset": [
    { "f": 0, "y": 0 }, { "f": 1, "y": -1 },
    { "f": 2, "y": 0 }, { "f": 3, "y": -1 }
  ]
}
```

**反向播放**（不需要自己的影格圖）：

```json
{
  "id": "stand_up",
  "type": "frames",
  "frames": 4,
  "frame_ms": 125,
  "desc": "站起。反向播放 sit_down。",
  "frames_dir": "build/strip/brown_mixed/sit_down_px",
  "reverse": true
}
```

**`transform` 型**（4/21 個：呼吸、轉身、開心、等待）：

```json
{
  "id": "idle_breathe",
  "type": "transform",
  "tier": 0,
  "loop": true,
  "frames": 4,
  "frame_ms": 750,
  "desc": "呼吸。整張 master 上下位移 1 px。",
  "track": [
    { "f": 0, "y": 0 }, { "f": 1, "y": -1 },
    { "f": 2, "y": -1 }, { "f": 3, "y": 0 }
  ]
}
```

```json
{
  "id": "turn",
  "type": "transform",
  "frames": 2,
  "desc": "轉身。純水平翻轉——master 必須是側面才有意義。",
  "track": [ { "f": 0 }, { "f": 1, "flip": 1 } ]
}
```

## 十一、和 `validate.py` 的分工

| 工具 | 管什麼 |
|---|---|
| `validate.py` | 21 個動畫齊不齊、影格數有沒有超預算、保護色的面積穩不穩定 |
| `bake.py` | 資料能不能真的合成出乾淨的像素影格 |

兩邊都要過。`validate.py` 是規格層的檢查，`bake.py` 是資產層的檢查，
沒有互相取代的關係。
