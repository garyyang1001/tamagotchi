# 05 — 資產管線

本文件記錄的多數規則是**實測踩出來的**，不是理論推導。每一條後面都附了實測數據。

---

## 管線總覽

```
真實照片 ──┐
           ├──→ mkprompt.py ──→ gpt-image-2 ──→ 原始輸出（不可直用）
specs/  ───┘   （組提示詞）      （只做設計）
  anim_prompt/                                     │
  characters/*.json                                │
  palettes/*.json                                  │
                        ┌────────────────────────┘
                        ↓
              一張含全部影格的圖（2×2 四格）
                        ↓ cutstrip.py    切開、對齊、面積正規化
                        ↓ pixelate.py    降採樣 + 語意重映射 + 保護色
                        ↓ pixedit.py     手工補 5px 以下（只有 master 需要）
              build/strip/<char>/<anim>_px/
                        ↓
        specs/animations/<char>.anim.json（純資料）
                        ↓ bake.py        整數平移 + 水平翻轉 + 疊圖
              build/sheets/  spritesheet + atlas
                        ↓ preview.py     GIF + 接觸表 + 實機模擬
                        ↓ pack.py        （未寫，先評估 lv_img_conv）
              data/assets.bin
```

**核心分工：AI 負責「設計」，`pixelate.py` 負責「資產」。**
不要期待模型直接產出可用檔案，也不要在管線裡手工修圖。

## 一、為什麼影像模型的輸出不能直接用

實測 gpt-image-2 產出「像素風」圖片的實際數據：

| 宣稱 | 實測 |
|---|---|
| 乾淨的像素網格 | 色塊長度 2 / 3 / 4 / 5 混雜，**網格不一致** |
| 10 色 | **27,990 色** |
| 純洋紅背景 `#FF00FF` | `#F703F5`、`#F803F5`、`#F702F5`… **10 幾種相近雜訊值** |
| 1024×1024 | 實際輸出 1341×1173，**指定尺寸不生效** |

視覺上像像素藝術，資料上完全不是。直接量化成 4bpp 會產生嚴重色帶，
RLE 壓縮率也會從 2.5× 掉到接近 1×。

**所有生成圖一律經過 `tools/pixelate.py`。**

## 二、`pixelate.py` 的四個步驟

### 1. 去背

以色度距離判斷前景。洋紅和四個角色的配色（棕、白、金、冰藍）在色相上都離得很遠，
`--tol 90` 就能把背景的所有雜訊值一併吃掉。

### 2. 預量化

**先把前景壓到 48 色，再做降採樣。**

不做這一步的話，28,000 色的來源在每個目標格內幾乎每個像素都是相異色，
取眾數等同於隨機挑一個像素，結果全是雜訊。

### 3. 眾數降採樣

每個目標格取「前景眾數色」，**不是平均值**。

平均值會在色塊邊界產生原本不存在的中間色——那正是像素藝術要避免的東西。
眾數則會乾淨地選擇該格的主導色。

`--coverage 0.45`：一格內前景比例低於 45% 就判為透明。
略低於半數，讓腿、尾巴、耳尖這些細長部位不會被吃掉。

### 4. 語意重映射

**這一步不能用「最近 RGB 距離」自動化。**

實測：把手工調色盤用最近距離套到 AI 產出上，狗身上的中棕色像素因為數值上
離 `muzzle_grey_dark` 比離 `coat_mid` 更近，**整片肚子和腿都被吸成灰白色**。

正確做法是 `--remap`：一張人工填寫的對照表，把 AI 的色群指到語意角色。

```bash
# 1. 先看 AI 自然分出哪些色群，產生範本
python tools/pixelate.py art/generated/foo.png --width 64 --colors 12 \
    --palette specs/palettes/brown_mixed.json --dump-clusters

# 2. 編輯產生的 foo_remap.json，把 TODO_ROLE 換成語意角色
#    {"#A37245": "tan_mid", "#CDA987": "muzzle_grey_light", ...}

# 3. 套用
python tools/pixelate.py art/generated/foo.png --width 64 --colors 12 \
    --palette specs/palettes/brown_mixed.json --remap art/generated/foo.remap.json
```

重映射同時具有**校正**功能。實測 AI 把老犬的灰白吻部畫成飽和度 70 的暖褐色，
指到 `muzzle_grey_light`（飽和度 26）後就校正成了規格要求的去飽和灰白。

> ⚠️ **重映射必須按部件做，不能按整張角色圖做。**
> 實測發現 AI 在吻部和小腿用了同一個色值 `#CDA987`，
> 整張圖一起 remap 會讓腳跟著吻部一起變灰。
> 切分成獨立部件檔之後，每個部件有自己的對照表，這個問題自然消失。

## 三、為什麼不在管線裡做旋轉

### 真正的問題不是旋轉，是重複降採樣

原本的想法是「在高解析度合成與旋轉，最後才像素化」。這條路線業界確實在用——
Donkey Kong Country 是預算繪 3D 壓成 SNES sprite，Dead Cells 是 3ds Max 建模
渲染成像素。但 Dead Cells 的美術總監 Thomas Vasseur 說：

> 我們到現在還是沒找到閃爍像素的任何解法。

原因在數字裡。本專案的降採樣比是 **21 : 1**：

| 部件 | 來源尺寸 | 目標像素 |
|---|---|---|
| `torso` | 589 × 351 | **28 × 17** |
| `head` | 317 × 236 | **15 × 11** |
| `leg_fore_near` | 140 × 352 | **6.7 × 16.8** |
| `eyelid` | 201 × 74 | **9.6 × 3.5** |

**一條腿只有 7 像素寬，眼瞼只有 3.5 像素高。**

「把後腿旋轉 25 度」在輸出端的全部意義，是把腿下段的 3 個像素往旁邊挪 2 格。
用 352×140 的連續值圖層去驅動一個只有 119 個像素的離散結果，
中間絕大部分資訊被丟棄——**而且丟棄哪些是由降採樣格線與旋轉角度的交互作用決定的，
不受我們控制**。那就是閃爍。

### 試過的解法，以及它為什麼也失敗

曾經有一條「兩階段烘焙」的路線：階段 A 把 16 個高解析部件旋轉組成 3-4 個關鍵姿勢、
降採樣**一次**產出七個像素領域圖層；階段 B 只對那些圖層做整數平移與疊圖。
閃爍的問題確實解掉了——但**動作本身是錯的**。

失敗的原因和降採樣無關：整條腿繞肩關節旋轉，腳掌會**畫弧離開地面**。
真實的腿是在膝肘彎曲、腳掌貼地推進，單段式部件做不到。
實測 `walk` 與 `idle_breathe` 產出**完全相同的影格**——狗不是在走路，是在飄。

整條路線（`assemble.py` / `cutparts.py` / `specs/poses/` / `art/rigs/`）
於 2026-08-01 移除，`bake.py` 裡的 `rig` 型於 2026-08-02 一併清掉。
還原點 git commit `04f5ed2`。**不要再走回去。**

### 現行做法：一次生成一張含全部影格的圖

**分開多次生成會漂移**——實測分三次生坐姿／趴姿／正面，三張全部朝同一方向漂移
（更圓更幼、灰白吻部退回暖褐）。

**但一張圖裡的多個元素不會漂移**，因為那是單次推理。
所以請模型一次畫出四格，再用 `cutstrip.py` 切開對齊。模型畫的腳掌是貼地的。

管線裡完全沒有旋轉，所以閃爍的問題根本不會出現。

### 三條鐵律

### 鐵律 1：所有影格共用同一組固定調色盤

```bash
python tools/pixelate.py frame_*.png --palette specs/palettes/<char>.json --remap ...
```

各格若各自做自適應量化，相鄰兩格會挑到略微不同的色階，
播放時整隻角色會**色彩閃爍**。

### 鐵律 2：動畫影格絕對不可以逐格裁切

```bash
python tools/pixelate.py frame_*.png --no-crop --width 64 --height 64 ...
```

每一格的內容範圍都不同，逐格裁切會讓降採樣的網格錨點在格與格之間漂移，
播放時角色會**整體抖動**。必須用固定的來源畫布，讓所有影格共用同一組格線。

`pixelate.py` 的 `--no-crop` 就是為此存在。單張設定圖用預設的裁切，
動畫影格一律加 `--no-crop`。

### 鐵律 3：烘焙不做任何重新採樣

只允許**整數像素平移**、**水平翻轉**、**z 排序**、**顯式像素 patch**。

不旋轉、不縮放、不做非整數位移。這條是前兩條的前提——
一旦烘焙動到採樣，鐵律 1 和 2 就白費了。

## 三之二、sub-pixel animation：零成本的細微動作

低解析度動畫最有價值、也最被誤解的技巧。它**不是**把東西移動半個像素，
而是「動畫化色階的歸屬」——剪影完全不動，只改哪些像素屬於哪個色階。

我們每個材質有 3 階（暗／中／亮），這正好是它需要的條件。
呼吸、頭部微轉、重心轉移都可以只改色階、不動剪影。

好處：
- **零額外影格**
- **物理上不可能閃爍**，因為像素座標根本沒動
- 在 `idle_breathe` 這種一直在播的動畫上，比上下移動 1px 更細膩

經典參考是 Metal Slug：剪影幾乎不動，顏色大幅位移。

## 四、生成端的實測規則

| 現象 | 對策 |
|---|---|
| 只寫 "pixel art" → 模型畫高細節圖再套濾鏡，等效解析度 150×160 | 提示詞明確寫 "originally drawn at only 64 x 56 pixels" 並強調 "genuinely low-resolution" |
| 一張圖放多個視角 → 各視角比例互相漂移（實測三視角就已經明顯） | **一次只生成一個姿勢**，設定圖分開生再自己拼版 |
| 強調「可愛」→ 中大型犬變成幼犬比例（實測變成臘腸犬） | 明確給出頭身比、腿長、體長與肩高的**數量關係** |
| **換姿勢會造成身分漂移，餵參考圖擋不住** | 見下方「一個角色只生一個姿勢」 |
| **5 像素以下的特徵控制不了**（眼睛只有 2–3 px） | `tools/pixedit.py` 手工畫 |
| **指定顏色打不準**（要飽和度 26 的灰白，實得 80 的暖褐） | `--remap` 校正 |

### 一個角色只生一個姿勢

實測：以已核可的 master 站姿為參考圖，明確指示「這是同一隻角色的不同姿勢，
不要重新設計、不要變得更可愛更年輕」，生成坐姿 / 趴姿 / 正面三張。

**三張全部失敗，而且朝同一個方向漂移**——變圓、變幼、灰白吻部退回暖褐色，
正面那張是徹底的重新設計。這是系統性的，不是運氣，再迭代也是擲骰子。

因此：

> **一個動作只生「一張」圖，四格畫在同一張圖裡。**

同一張圖內的元素不會漂移（單次推理），跨圖才會。所以 `sit_down` 的四格
一定要在同一張圖上，而 `sit_down` 與 `lie_down` 是兩張沒關係——
它們之間的一致性靠**同一張 master 當參考圖**維持。

> **⚠️ 撤回**：本節原本寫「在 64px 上解剖學的精確度看不出來，
> 後腿摺疊的差異用旋轉加位移足夠」。**那是錯的，理由完全相反。**
>
> 正因為 64px 上只剩剪影可讀，坐姿與站姿**如果剪影相同就是同一個姿勢**。
> 像素藝術的第一原則就是剪影可讀性。姿態必須換剪影——
> 這也是提示詞裡「a sitting dog is a different shape, not the same shape
> made shorter」那句話的由來。
| gpt-image-2 不支援透明背景 | 統一用純洋紅 `#FF00FF` 再去背。要真透明得退回 gpt-image-1.5，但那個模型像素風表現較差 |
| 指定尺寸不生效 | 不要依賴輸出尺寸，`pixelate.py` 會裁到內容範圍再縮放 |

## 四之二、場景與物件：另一條管線

房間與物件**不走 AI 那條路**。判準很簡單：

| 東西 | 特性 | 誰做 |
|---|---|---|
| 角色 | 造型、剪影、毛色分佈——設計問題 | AI 生 → 管線轉成資產 |
| 房間 | 牆、地板、地毯、窗框——**幾何** | `tools/scene.py` 直接算 |
| 物件 | 碗 15×9、球 10×9、睡墊 44×13——**5px 級的細節** | JSON 裡逐像素寫 |

讓 AI 畫房間只會多一輪 28,000 色的重映射，而且窗框會歪、地板接縫會抖——
那些正是像素領域一行程式就能保證的東西。物件則本來就落在「5 像素以下手工畫」那一格。

### 日夜共用同一張點陣圖

底圖只算一次，套兩份調色盤（`scene.json` / `scene_night.json`，角色編號逐一對應）。
這保證日夜完全對齊——做不出「夜間版的窗戶少了一格」這種錯，而且省一份 flash。
`scene.py` 會擋下兩份調色盤角色順序不一致的情況。

和公主的服裝置換是同一招。

### 物件只拆「放在地上的」

判準是**它會不會離開角色的身體**：

* 飯碗放在地上 → 拆。由渲染層畫在吻部下方，錨點逐角色記在 `specs/scene.json`
  （實測三隻狗的吻部落點差 10 px）
* 球被丟出去要自己飛 → 一定要拆
* **公主捧在手上的碗不拆** → 它跟著手動，只能留在影格裡

原本四隻的碗全烘在影格裡，三隻狗的碗**根本讀不出來**（吻部下方一團深色，
和頭連在一起），而 `chase_ball` 更是完全沒有球——公主丟一顆看不見的球、
狗追一顆不存在的球。

### 物件的四種擺放模式

`y` 該不該由人填，取決於物件有沒有接地。這是四種模式存在的唯一理由：

| 模式 | 誰 | x | y |
|---|---|---|---|
| `ground` | 飯碗、睡墊 | `slot.x + anchor_x` | `ground_y − dy − base_row` |
| `float` | 愛心 | 相對角色影格左上角 | 同左，**由人填是對的**（不接地，沒有基準） |
| `fixed` | 窗外的雪 | 螢幕絕對座標 | 同左 |
| `track` | 球 | 逐格絕對座標 | 同左 |

`base_row` 是物件**自己宣告**哪一列踩在地面線上，預設是最底列。
睡墊宣告第 13 列——它是俯視角度的，底緣對齊地面線的話會被趴著的角色完全蓋住
（實測狗趴下有 48–64 寬）。底下那 8 列是朝向觀眾的近側邊緣，露在角色前面才看得到。

前一版把所有物件塞進同一個 `[x, y]` 欄位，結果對狗成立、對公主差 40 px——
影格高度不同（56 vs 96），而 y 是相對影格頂端算的。

### 物件只在需要時出現

平時房間是空的，點餵食才出現碗、點玩才出現球。
320 px 的寬度扣掉四個角色的 226 只剩 94，同時放下全部物件會擠爆；
而且畫面越乾淨，三歲小孩越容易鎖定角色。

## 五、Flash 用量驗算

```
單格 sprite（狗，64×53，4bpp 索引）
  原始      64 × 53 ÷ 2  = 1,696 B
  RLE 後（平塗限色，實測 2.5×）  ≈ 680 B

動畫總數 90 個 × 平均 9 格 = 810 格
810 × 680 ≈ 550 KB
加上物件 / UI / 場景 / 服裝  ≈ 900 KB
```

`assets` 分區 **6 MB** → 餘裕 **6.7×**。

對照：原始規劃的 250 張 128×128 RGB565 未壓縮 = **7.81 MB**，
已經超過整片 flash 扣掉韌體後的可用空間。
現在動畫數量多 3 倍，佔用只有 **11.5%**。

## 六、指令速查

```bash
# 探索階段：看看 AI 產出縮到目標尺寸長什麼樣
python tools/pixelate.py art/generated/foo.png --width 64 --colors 12

# 產生語意對照表範本
python tools/pixelate.py art/generated/foo.png --width 64 --colors 12 \
    --palette specs/palettes/brown_mixed.json --dump-clusters

# 正式資產：語意重映射
python tools/pixelate.py art/generated/foo.png --width 64 --colors 12 \
    --palette specs/palettes/brown_mixed.json --remap art/generated/foo.remap.json

# 動畫影格：整條管線一行搞定（cutstrip → pixelate → automap → pixelate）
sh tools/procanim.sh brown_mixed walk
```

`procanim.sh` 會自動帶上 `--character`（影格尺寸來自角色規格檔）與
`--match-area`（面積對齊 master）。**不要手動拆開跑**——
`--no-crop` 與 `--height` 缺一不可，逐格裁切會讓降採樣的格線漂移（鐵律 2）。
